# Experimental legacy text reader contract

## Scope and evidence

INFERENCE: a separate experimental crate may recover linked text segments and root-size metadata from the legacy A, B and third-family profiles below. It must remain separate from the 2002+ importer. Its output is text, provenance, size candidates and diagnostics; it creates no frames, pages or layout objects. This document is a proposed reader contract, not an implementation or a claim that every Publisher 97/98/2000 file is decoded.

OBSERVATION: this contract consolidates the [A notes](legacy-97-2000-contents-a.md), [B notes](legacy-97-2000-contents-b.md), [replication and third-family text findings](legacy-97-2000-replication.md), the bounded section-directory definitions in [text-store.md](text-store.md), and identities already recorded in [SOURCES.md](SOURCES.md). No new binary research, other reader, external format description or specification is used for this document. Later replication/AP20/AP21 findings supersede the earlier checkpoints' availability and text-link unknowns.

OBSERVATION: the documented evidence comprises nine distinct binary identities. A reattachment of mspub is not another sample; Sample98 and Sample2000 have identical TEXT payloads, and mspub/zmspub have identical empty Quill streams. File counts therefore do not prove independently varied text content. The following table gives the complete file sets used by every coverage reference in this contract.

### C text fields

OBSERVATION / C: S=u32(C+0x0E), P=u32(C+0x12), M=P-S. The core is Contents [S,P); the AP20 candidate buffer includes the CR/LF trailer [P,P+2). Five cores have 5262/6845/6768/7108/10562 bytes. There is a form feed at P-1, CR/LF at P, then zeros to the next 512-byte boundary before D. The rest of the pre-directory region is not decoded.

OBSERVATION / C: exactly one index-26/class-10 record occurs per file. Set T=R+H, n=u16(T), duplicate=u16(T+2), w=u16(T+4). Both counts agree, n is positive/even and w=10. Require n u32 slots at A, an extra u32 at A+4*n equal to M, and n ten-byte elements at B, all within E. Their independent total H+22+n*(4+10) equals E-R.

OBSERVATION / C: for j from zero through n/2-1, slots 2*j and 2*j+1 are byte start/end relative to S. There are 292/292 linked ranges, ending in CR/LF then form feed; the final two-byte trailer is unmapped. The target ID is not a Quill story ID. ## Required gates and exact failure rules

INFERENCE: the following are conservative reader policies, not newly observed format laws. Refuse means emit no story from the failed unit. File refusal invalidates all results; text-path refusal can retain independently checked raw size candidates; segment refusal permits other independently valid segments with an explicit partial-recovery warning. Metadata failure withholds size only. Every diagnostic names `experimental legacy A`, `B`, `C` or `legacy family unknown`, the failed field/range or record ID, and whether corruption, an unsupported profile or a resource limit was observed. It does not assert an exact release or echo private text.

INFERENCE: no result may be published before the shared tables and that result's complete dependency chain are validated. All offset additions, products, count-derived allocations, range conversions and traversal limits use checked arithmetic. As an initial operational policy, refuse files or individual extracted streams above 32 MiB, more than 65535 recovered segments/IDs, or Quill chains above 64 blocks; these are experimental limits, not format facts. Counts must also fit remaining bytes before allocation. No retry may relax a limit or reinterpret a failed field.

## Page-size output and must-not-claim boundary

OBSERVATION: root raw pairs have nine-file support, while dividing by 36000 gives numerical A4, Letter, half-Letter and custom-square candidates. The existing notes have no independent physical measurement proving this unit or that every root pair is a physical page. Matching pairs in index 44 corroborate storage, not units. Positive geometry once rested on one A and one B file, and third-family half-root containment fails in 58 linked records; none of that is a page-size oracle.

INFERENCE: the output may expose the checked raw root pair as a root-size candidate, and optionally the explicitly **INFERRED** conversion W/36000 and H/36000 millimetres (or W/12700 and H/12700 points) with a named uncertainty warning. It must not label that conversion a verified physical page size. If an API requires a verified physical size, that field is UNKNOWN and must remain absent. Size failure does not authorize a guessed A4/Letter default. A duplicate-pair probe is optional corroboration, not permission to substitute another record's standard-looking values.

INFERENCE: the minimal reader must not claim exact saving release; page count/identity/order; frame creation, positions, dimensions or coordinate transforms; reading order or threading; fonts, glyph coverage, styles, colours, fills, borders, geometry, margins, columns, rotation, tables/cells, pictures, embedded-object text, fields, visible/hidden/overset status or native editability/layout fidelity. Record IDs are opaque provenance, not frames. Storage order is not visual order. It must not expand control codes into page numbers/dates or silently strip markers, normalize paragraph endings, repair files, infer unknown tags or use the current importer as an undocumented fallback.

UNKNOWN: exact C code page, marker rendering and empty-store representation; general B tag/slot behavior; authoritative A/B Contents story-ID width; duplicate count authority, unknown class extents and internal padding; root/page semantics and physical scale; wider sample/version coverage. These remain limits even when every mechanical safety check succeeds. A text-only result is not a recovered Publisher document.

## Synthetic fixture specification

INFERENCE: future tests should construct containers and streams entirely from these field relationships, using an allowed container writer and deterministic bytes invented by the test. This is a specification for tests, not test code or evidence that the invented files were produced by Publisher. Do not copy a native file, a native layout-table blob, private text, pictures or other sample payloads into the repository. Synthetic passing cases must not be counted as independent confirmation of FRAGILE format findings.

INFERENCE: define reusable complete positive models, then mutate one relationship at a time. Compute C, D, all section/record offsets, actual stream lengths and directory ends from the generated structures. Fill uninstantiated table entries deterministically, and instantiate only descriptors whose required shape is defined above. Keep the required A/B/C entry count and index convention; place all terminators inside the declared table region. These tests deliberately relocate the control, directory and sections so a sample-offset lookup cannot pass. Where guards overlap, accept a precise earlier refusal for the same corruption, and separately exercise the affected local validator; do not require a particular internal execution order to hide an untested check.

## Code page of the single-byte text (families C and D), 2026-11-22 (donated files, local only)

OBSERVATION: across the five C files and the eight D files, the bytes at or above 0x80 in the text buffers are, with their neighbours (read as ASCII): 0x93 before a word and 0x94 after a sentence (`Lorem ip...` template text in JAZZY, MODERN and PLAIN; a quoted phrase in the VIW-CCS-SA flyer and in SCHOOL), 0x92 between a name or noun and a following `s` (`Diner|s Club` in JAZZY, MODERN and PLAIN; `reader|s`, `Peter|s`, `another|s` in SCHOOL, WEDDINGC and WEDPROP), and 0xa9 before a four-digit year (`| 1996` in HLFOFFSP, three times). One 0xc2 follows `TEXT` in PLAIN and is the only byte that does not fit.

INFERENCE: read as Windows-1252, those bytes are curly double quotes, a typographic apostrophe and a copyright sign, in the places they would be typed. Mac Roman would make 0x92 an accented letter inside `Diner s` and `reader s`, and 0x93 and 0x94 accented letters at the edges of quoted phrases, which no word supports. The reader therefore decodes single-byte text as Windows-1252 and says so in a warning: "inferred, not confirmed". UNKNOWN: whether every file uses it (all thirteen with high bytes agree), the 0xc2 in PLAIN (it decodes to a capital A with a circumflex), and Windows-1252's five undefined bytes (0x81, 0x8d, 0x8f, 0x90, 0x9d): a segment that holds one stays undecoded, as before. This replaces the earlier rule that every byte at or above 0x80 leaves its segment undecoded; ASCII-only segments are exact and are not marked.

## Page size of the text-only profile, 2026-11-22 (donated files, local only)

OBSERVATION: in the eight files of the header +4 = 0x00c8 profile, the record directory is at header +0x16 (count u16, maximum id u16, four more bytes, then 10-byte entries: record offset u32, attribute u16, id u16, parent u16; offsets ascend). Exactly one record in each file starts with the word 21 and has prefix length 84 (byte +3); it is the root, as in the other profiles. Its size pair at +0x14 and +0x18 is 7772400 x 10058400 in five files, 5029200 x 7772400 in one, 7772400 x 10058400 in another and 3200400 x 1828800 in the business card. At 914400 units per inch these are 8.5 x 11, 5.5 x 8.5 and 3.5 x 2 inches. The business card agrees with the stored text (two cards' worth of name, title and address lines). Together with the Letter and half-Letter pairs of the other profiles, this supports the 914400-per-inch unit. The other record types of this profile do not carry the rectangles that the A and B records carry at +0x06, so no frame position is read.

INFERENCE: the reader returns the root pair as the size candidate when the directory, the ascending offsets, the single root and non-zero sides all check out, and withholds only the size otherwise. The opener uses it as the recovery page, except that a text-only recovery whose shorter side is under four inches is flowed on A4, because the text is not placed on that page and would otherwise spread over many tiny pages (the business card gave 13 pages).

## Border widths and the flag bit, 2026-11-22 (donated files, local only)

OBSERVATION (desktop test, Flyer 200201): the per-side border numbers at +0x2c, +0x35, +0x3b and +0x41 of a text frame are 0x81 on the two tall khaki and white columns, which have no thick border on the stored preview. Read as the whole byte (129) and clamped to 36 points, they drew a black outline 36 points thick around those frames; that outline is the large dark area of the first desktop capture and also took the text space that made the left column run off the page. With the flag bit 0x80 masked off the number is 1.

INFERENCE: bit 0x80 is a flag, not part of the width; the width is the low seven bits. Numbers above 8 after masking have not been seen on a bordered frame, so they are not read as a width (UNKNOWN). After the change the page renders close to the stored preview, and the text fits (checked by eye on that file).
