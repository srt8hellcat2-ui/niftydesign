# Experimental legacy text reader contract v2

INFERENCE: version 2 incorporates the policy clarifications from [the reader review](legacy-reader-review.md). These are conservative reader requirements, not new format discoveries. Every FRAGILE qualification and UNKNOWN below remains applicable. The implementation re-review is pinned to `fbab857f`; a requirement here does not assert that revision implements it.

## Scope and evidence

INFERENCE: a separate experimental crate may recover linked text segments and root-size metadata from the legacy A, B and third-family profiles below. It must remain separate from the 2002+ importer. Its output is text, provenance, size candidates and diagnostics; it creates no frames, pages or layout objects. This document is a proposed reader contract, not an implementation or a claim that every Publisher 97/98/2000 file is decoded.

OBSERVATION: this contract consolidates the [A notes](legacy-97-2000-contents-a.md), [B notes](legacy-97-2000-contents-b.md), [replication and third-family text findings](legacy-97-2000-replication.md), the bounded section-directory definitions in [text-store.md](text-store.md), and identities already recorded in [SOURCES.md](SOURCES.md). No new binary research, other reader, external format description or specification is used for this document. Later replication/AP20/AP21 findings supersede the earlier checkpoints' availability and text-link unknowns.

A reattachment of mspub is not another sample; Sample98 and Sample2000 have identical TEXT payloads, and mspub/zmspub have identical empty Quill streams. ## Required gates and exact failure rules

INFERENCE: the following are conservative reader policies, not newly observed format laws. Refuse means emit no story from the failed unit. File refusal invalidates all results; text-path refusal can retain independently checked raw size candidates; segment refusal permits other independently valid segments with an explicit partial-recovery warning. Metadata failure withholds size only. Every diagnostic names `experimental legacy A`, `B`, `C` or `legacy family unknown`, the failed field/range or record ID, and whether corruption, an unsupported profile or a resource limit was observed. It does not assert an exact release or echo private text.

INFERENCE: no result may be published before the shared tables and that result's complete dependency chain are validated. All offset additions, products, count-derived allocations, range conversions and traversal limits use checked arithmetic. As an initial operational policy, refuse files or individual extracted streams above 32 MiB, more than 65535 recovered segments/IDs, Quill chains above 64 blocks, or aggregate Quill section counts above 100000; these are experimental limits, not format facts. The stream budget applies to declared length before reading and delivered length afterwards; delivered length must equal declared length. Counts must also fit remaining bytes before allocation. Use checked arithmetic on the supported host width; no count may cause an unchecked intermediate addition or product. Parent-graph validation must take O(N) traversal/membership work, using constant-time active/settled membership rather than repeatedly searching a growing path. These work bounds are resource policy, not format semantics. No retry may relax a limit or reinterpret a failed field.

### Story provenance and completeness

INFERENCE: a positive SYID catalog with any zero STRS length is an unsupported text partition and refuses the text path; a failed story must never become an empty slice. Emit a validated A/B story ID once, retaining its UTF-16-unit range, Quill stream/catalog identity and every validated linking Contents record ID. Preserve deterministic storage order only; duplicated references prove neither reading order nor threading. C output retains the source map ID, target record ID and byte range relative to S, not a fabricated Quill ID.

INFERENCE: Complete means every supported linked candidate was recovered, not every text location in the publication. Count and warn about positive catalog IDs without a validated Contents link; retain their status as unclaimed catalog entries, never output linked stories for them. Report failed candidates separately from merely unlinked IDs. EmptyKnownStore is allowed only by AB08; zero decodes due to unsupported encoding or failed candidates is Partial/unrecovered.

## Page-size output and must-not-claim boundary

OBSERVATION: root raw pairs have nine-file support, while dividing by 36000 gives numerical A4, Letter, half-Letter and custom-square candidates. The existing notes have no independent physical measurement proving this unit or that every root pair is a physical page. Matching pairs in index 44 corroborate storage, not units. Positive geometry once rested on one A and one B file, and third-family half-root containment fails in 58 linked records; none of that is a page-size oracle.

INFERENCE: the output may expose the checked raw root pair as a root-size candidate, and optionally the explicitly **INFERRED** conversion W/36000 and H/36000 millimetres (or W/12700 and H/12700 points) with a named uncertainty warning. It must not label that conversion a verified physical page size. If an API requires a verified physical size, that field is UNKNOWN and must remain absent. Size failure does not authorize a guessed A4/Letter default. A duplicate-pair probe is optional corroboration, not permission to substitute another record's standard-looking values.

INFERENCE: the minimal reader must not claim exact saving release; page count/identity/order; frame creation, positions, dimensions or coordinate transforms; reading order or threading; fonts, glyph coverage, styles, colours, fills, borders, geometry, margins, columns, rotation, tables/cells, pictures, embedded-object text, fields, visible/hidden/overset status or native editability/layout fidelity. Record IDs are opaque provenance, not frames. Storage order is not visual order. It must not expand control codes into page numbers/dates or silently strip markers, normalize paragraph endings, repair files, infer unknown tags or use the current importer as an undocumented fallback.

UNKNOWN: exact C code page, marker rendering and empty-store representation; general B tag/slot behavior; authoritative A/B Contents story-ID width; duplicate count authority, unknown class extents and internal padding; root/page semantics and physical scale; wider sample/version coverage. These remain limits even when every mechanical safety check succeeds. A text-only result is not a recovered Publisher document.

## Diagnostic contract

INFERENCE: every refusal or withholding diagnostic must expose the fields below, as structured data or an unambiguous labelled message. A string-only API is acceptable only if it preserves every field. This specifies v2 output; it does not assert that the pinned crate implements it.

| Basis | Required field | Exact values or meaning |
| --- | --- | --- |
| INFERENCE | category | `NOT_LEGACY`, `MALFORMED`, `UNSUPPORTED`, `LIMIT`, or `NOTICE`, defined below. |
| INFERENCE | family | `experimental legacy A`, `experimental legacy B`, `experimental legacy C`, or `legacy-family-unknown` before complete structural admission. |
| INFERENCE | gate | Responsible gate ID G01–G09, AB01–AB08, C01–C06 or O01. |
| INFERENCE | field | Stable structural location such as `Contents.header.length`, `CFB.version` or `Contents.record.profile`; never document text or a private path. |
